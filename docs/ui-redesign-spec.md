# Muse 前端 UI 改造需求文档

> 参考对象：Google AI Studio UI 风格
> 技术栈：Vue 3 + TypeScript + Naive UI + Vite
> 兼容要求：PC端 + 移动端（响应式）

---

## 一、改造总览

### 1.1 改造目标

将 Muse 前端从现有的「多页面 + 左侧导航菜单」架构，改造为类似 Google AI Studio 的「**对话为核心 + 左右侧边栏面板 + 中间路由视图切换**」架构。核心理念：

- **中间主区域默认展示对话内容**，聊天是最核心的交互
- **中间主区域同时承担编辑器职能**：当用户在右侧面板点击了具体的预设/世界书/正则项后，通过路由跳转，中间区域切换为对应的**全尺寸编辑视图**，充分利用主区域的大面积空间
- **左侧边栏**：放置会话历史列表、新建对话、角色选择等导航功能
- **右侧面板**：作为**列表选择器**，展示预设列表、世界书列表、正则列表、模型配置等。用户在右侧面板中**选择具体项**，通过路由导航到对应的编辑器视图
- **保留路由机制**：所有功能页面（对话/预设编辑/世界书编辑/正则编辑）都有独立路由，但共享同一个三栏布局框架。这样既保持 Google AI Studio 的沉浸式体验，又保留路由带来的浏览器前进/后退、URL 可书签可分享、代码按路由自然分割等优势
- 设置页面改为全局 Drawer 抽屉形式

### 1.2 核心交互模式

**"右侧选择 → 中间编辑"** 的联动模式：

```
用户操作流程示例：
1. 用户在中间区域进行对话（默认视图）
2. 用户点击顶部/右侧按钮打开右侧面板
3. 右侧面板默认显示模型配置 Tab，也可切换到预设/世界书/正则 Tab
4. 用户在右侧面板的"预设" Tab 中看到预设列表，点击某个具体预设
5. 中间主区域从"对话视图"切换为"预设编辑视图"，全尺寸展示预设编辑器
6. 用户编辑完成后，点击"返回对话"按钮，中间区域切回对话视图
```

### 1.3 现有架构 vs 目标架构

**现有架构：**
```
┌──────────┬────────────────────────────────┐
│ 左侧导航 │       单一路由的页面内容            │
│ (固定菜单) │   (聊天/角色/世界书/预设/正则/设置)  │
│          │                                │
└──────────┴────────────────────────────────┘
```

**目标架构（路由共享布局模式）：**
```
┌──────────┬──────────────────────────┬───────────┐
│ 左侧边栏  │        中间主区域           │ 右侧面板   │
│ (可折叠)  │  ┌──────────────────┐    │ (列表选择) │
│          │  │ 默认：对话视图     │    │           │
│ · 新建对话 │  │ ─ 或 ─           │    │ Tab切换：  │
│ · 会话历史 │  │ 预设编辑视图      │    │ · 模型配置 │
│ · 角色选择 │  │ ─ 或 ─           │    │ · 预设列表 │
│           │  │ 世界书编辑视图    │    │ · 世界书列表│
│           │  │ ─ 或 ─           │    │ · 正则列表 │
│           │  │ 正则编辑视图      │    │           │
│           │  └──────────────────┘    │           │
└──────────┴──────────────────────────┴───────────┘
```

### 1.4 路由改造方案

**保留路由 + 共享三栏布局**：所有路由共享同一个 `AppLayout`（左侧边栏 + 中间 `<router-view>` + 右侧面板），通过路由切换中间区域内容，视觉上仍然是「单页沉浸式」体验，用户感受不到页面跳转。

| 现有路由 | 改造方案 | 说明 |
|---------|---------|------|
| `/` (ChatView) | **保留** | 主页面，中间区域展示对话视图 |
| `/characters` | **取消独立路由** | 整合到左侧边栏的角色选择面板（非编辑功能，无需独立路由） |
| `/preset/:id` | **新增** | 右侧面板选择预设 → `router.push('/preset/:id')` → 中间区域展示预设编辑器 |
| `/worldinfo/:id` | **新增** | 右侧面板选择世界书 → `router.push('/worldinfo/:id')` → 中间区域展示世界书编辑器 |
| `/regex/:id` | **新增** | 右侧面板选择正则 → `router.push('/regex/:id')` → 中间区域展示正则编辑器 |
| `/settings` | **取消独立路由** | 改为全局 Drawer 抽屉（设置内容简单，无需路由） |
| `/login` | **保留** | 登录页保持不变（独立布局，不共享三栏框架） |

**路由优势：**
- ✅ 浏览器前进/后退正常工作（用户编辑预设后可按后退键回到对话）
- ✅ URL 可书签、可分享（如 `/preset/abc123` 可直接打开某个预设编辑器）
- ✅ 代码自然分割，各视图组件通过 `lazy import` 按需加载
- ✅ 视觉上还是「单页沉浸式」体验，三栏布局始终保持不变

### 1.5 中间主区域路由视图

中间主区域通过 `<router-view>` 渲染当前路由对应的视图组件，不需要额外的状态变量控制：

```typescript
// 路由即视图，路由路径自动决定中间区域展示的内容
// /           → ChatView（对话视图）
// /preset/:id → PresetEditorView（预设编辑视图）
// /worldinfo/:id → WorldInfoEditorView（世界书编辑视图）
// /regex/:id → RegexEditorView（正则编辑视图）
```

- `chat`：默认对话视图（消息列表 + 输入框）
- `presetEditor`：预设编辑视图（全尺寸预设编辑器）
- `worldInfoEditor`：世界书编辑视图（全尺寸世界书编辑器）
- `regexEditor`：正则编辑视图（全尺寸正则规则编辑器）

## 二、整体布局设计

### 2.1 PC 端布局（≥ 1024px）

```
┌─────────────────────────────────────────────────────────────────┐
│ [☰] Muse                              [模型选择▼]  [⚙] [👤]    │  ← 顶部栏（高度 56px）

│  左侧边栏   │          中间主区域                 │   右侧面板      │

│  可折叠     │                                   │   可折叠        │
│            │  ┌─────────────────────────────┐  │                │
│ ┌────────┐ │  │                             │  │ ┌────────────┐ │
│ │+ 新对话 │ │  │   对话视图（默认）             │  │ │[模型][预设] │ │
```

**关键参数：**
- 顶部栏高度：`56px`
- 左侧边栏宽度：展开 `280px`，折叠 `0px`（完全隐藏，通过顶部☰按钮控制）
- 右侧面板宽度：展开 `320px`，折叠 `0px`（完全隐藏）
- 中间主区域：自适应剩余空间，`min-width: 480px`
- 所有面板使用 `transition` 动画过渡

### 2.2 平板端布局（768px ~ 1023px）

- 左侧边栏默认**折叠/隐藏**，点击☰按钮以 **Drawer 抽屉**形式从左侧滑出覆盖，带半透明遮罩
- 右侧面板默认**隐藏**，以 **Drawer 抽屉**形式从右侧滑出覆盖
- 中间主区域占满全屏
- 顶部栏保留，简化布局

- 左侧边栏：点击☰按钮，从左侧以 **全屏 Drawer** 滑出
- 右侧面板：点击顶部配置按钮，从右侧/底部以 **Drawer** 滑出
- 顶部栏简化，模型选择用紧凑下拉
- 编辑视图在移动端同样全屏展示，顶部带返回按钮
- 输入框固定在底部，键盘弹起时自动上推

## 三、顶部栏（Top Bar）详细设计

### 3.1 布局结构

```
┌──────────────────────────────────────────────────────────────────┐
│ [☰]  Muse  │ [← 返回对话](编辑视图时) │ [模型选择▼] │ [📋] [⚙] [👤] │
│  左侧       │     视图切换指示          │   中间区域   │     右侧       │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 元素说明

| 元素 | 位置 | 功能 | 交互 |
|-----|------|------|------|
| ☰ 汉堡菜单 | 最左 | 切换左侧边栏显隐 | 点击展开/收起左侧边栏 |
| Muse Logo | 紧跟☰后面 | 品牌标识 | 点击回到对话视图 |
| ← 返回对话 | Logo 右侧（仅编辑视图时显示） | 从编辑视图返回对话 | 点击切回对话视图 |
| 视图标题 | 中间偏左（仅编辑视图时显示） | 显示当前编辑内容标题 | 如"编辑预设: Default"，纯展示 |
| 模型选择下拉 | 中间 | 选择当前使用的 AI 模型 | 下拉选择，显示模型名+图标 |

| 👤 用户头像 | 最右 | 用户菜单 | 下拉显示：主题切换、退出登录 |

### 3.3 顶部栏在不同视图下的表现

**对话视图时：**
```
[☰]  Muse                    [模型选择▼]           [📋] [⚙] [👤]
```

**编辑视图时（如预设编辑）：**
```
[☰]  [← 返回对话]  编辑预设: Default               [📋] [⚙] [👤]
```
- 模型选择器在编辑视图时隐藏或移到右侧面板中
- 返回按钮突出显示，方便用户随时切回对话

### 3.4 样式要求

- 高度：PC `56px`，移动端 `48px`
- 背景：使用半透明毛玻璃效果 `backdrop-filter: blur(10px)`
- 边框：底部 `1px solid var(--border-color)`
- 固定定位：`position: sticky; top: 0`
- z-index：`100`
- Google AI Studio 风格：简洁、轻量，没有过重的阴影

### 3.5 模型选择器

模仿 Google AI Studio 的模型选择器样式：
- 外观：类似一个带边框的圆角按钮/选择器
- 内容：显示「模型图标 + 模型名称 + ▼箭头」
- 下拉面板：列出所有可用模型，支持搜索筛选
- 每个模型项显示：图标、名称、简短描述
- 选中态有高亮标记

## 五、中间主区域（Main Area）详细设计

中间主区域是整个应用的核心，它支持**多视图切换**：默认显示对话，当用户在右侧面板点击了具体的预设/世界书/正则后，切换为对应的全尺寸编辑器。

### 5.1 视图切换机制

```typescript
// 视图状态
type MainViewType = 'chat' | 'presetEditor' | 'worldInfoEditor' | 'regexEditor';

// 当前编辑目标
interface MainViewState {
  currentView: MainViewType;       // 当前视图类型
  editingPresetId: string | null;  // 正在编辑的预设 ID
  editingWorldInfoId: string | null; // 正在编辑的世界书 ID
  editingRegexId: string | null;   // 正在编辑的正则 ID
}
```

**视图切换规则：**
- 默认视图为 `chat`
- 用户在右侧面板点击某个预设 → `currentView = 'presetEditor'`，`editingPresetId = 具体ID`
- 用户在右侧面板点击某个世界书 → `currentView = 'worldInfoEditor'`，`editingWorldInfoId = 具体ID`
- 用户在右侧面板点击某条正则 → `currentView = 'regexEditor'`，`editingRegexId = 具体ID`
- 用户点击顶部栏"返回对话" / 左侧边栏切换会话 / 新建对话 → `currentView = 'chat'`

#### 5.2.3 消息气泡设计

**角色/AI 消息：**

- 头像：左侧显示角色头像（`32px` 圆形）

- 长文本消息支持折叠/展开

**用户消息：**
- 对齐方式：右对齐
- 无头像或显示用户头像
- 气泡背景：主题色（如蓝色/紫色渐变）或浅色
- 底部操作栏（hover 时显示）：编辑、删除

**消息交互：**
- hover 消息：显示操作按钮栏
- 消息编辑：点击编辑后，气泡内容变为可编辑输入框
- 流式输出：AI 回复时显示打字动画效果，消息逐字/逐段出现
- 消息之间间距：`16px`

#### 5.2.4 消息输入框设计

参考 Google AI Studio 的输入框：

**PC 端：**
- 位置：主对话区域底部，水平居中

- 样式：圆角矩形（`border-radius: 24px`），带边框

  - 右侧：发送按钮（有内容时高亮，无内容时灰色禁用）

- 输入框下方小字：显示当前模型名、token 统计

**移动端：**
- 固定在屏幕底部
- 宽度 `100% - padding`

### 7.2 功能详细说明

#### 7.2.1 预设基本信息
- **预设名称**：可编辑的文本输入框，位于编辑器最上方
- **编辑器顶部栏**：显示返回按钮、预设名称、保存/另存为按钮

#### 7.2.2 Prompt 列表（核心功能）
- 每个 Prompt 项是一个**可折叠的卡片**
- **展开态**显示完整编辑内容：
  - 角色下拉选择：系统（System）/ 用户（User）/ 助手（Assistant）

  - 支持 `{{char}}`、`{{user}}`、`{{description}}` 等宏变量，编辑器中可高亮显示这些变量
- **折叠态**只显示：名称、角色类型标签、启用状态
- **拖拽排序**：每个 Prompt 项左侧有拖拽手柄（`☰`图标），支持拖拽调整顺序

- 每条规则显示：启用开关、名称

- **[+ 添加正则]**：新增正则规则

#### 7.2.4 保存行为
- **自动保存**（推荐）：编辑内容实时自动保存，使用防抖（`debounce 1000ms`）
- **手动保存**（备选）：顶部栏有明确的保存按钮
- **另存为**：将当前预设复制为新预设

### 7.3 与右侧面板的联动

- 当预设编辑视图打开时，右侧面板的预设列表中对应项保持**高亮选中**
- 用户在右侧面板点击另一个预设 → 中间编辑器**无缝切换**到新预设（先保存当前编辑，再加载新预设）
- 如果用户在预设编辑视图中修改了预设名称，右侧面板列表中的名称也实时更新

### 7.4 样式要求

- 编辑内容最大宽度：`960px`，居中显示
- Prompt 卡片：
  - 圆角 `8px`，边框 `1px solid var(--border-color)`
  - 展开态内部 padding `16px`
  - 折叠态高度 `48px`
  - 卡片之间间距 `8px`
- 文本编辑器：
  - 等宽字体
  - 行号显示（可选）
  - 宏变量语法高亮
- 拖拽时的视觉反馈：半透明 + 阴影

### 8.2 功能详细说明

- **世界书名称**：可编辑的文本输入框
- **全局设置**：递归扫描开关、扫描深度、Token预算等

#### 8.2.2 词条列表（核心功能）
- 每个词条是一个**可折叠的卡片**
- **展开态**显示完整编辑内容：
  - **关键词**：Tag 输入框形式，支持多个关键词（逗号分隔或回车添加）
  - **辅助关键词**：可选，用于更精确的匹配
  - **触发方式**：下拉选择（关键词匹配、常驻、角色专属等）
  - **插入位置**：下拉选择（系统提示前/后、角色描述前/后、对话历史前/后等）
  - **优先级**：数字输入框
  - **状态**：启用/禁用下拉
  - **内容**：**全宽多行文本编辑器**，高度自适应，最小 `120px`
  - **Token 计数**：实时显示该词条的 Token 数量
- **折叠态**显示：词条标题、关键词预览（Tag 形式）
- **拖拽排序**：支持拖拽调整词条顺序
- **搜索过滤**：顶部搜索框可按关键词或内容过滤词条

- 多选模式：长按或勾选多个词条
- 批量操作：批量启用/禁用、批量删除、批量移动

- 在编辑视图内修改世界书名称/词条数量，右侧面板实时更新

### 8.4 样式要求

- 编辑内容最大宽度：`960px`，居中显示
- 词条卡片样式同预设编辑器的 Prompt 卡片
- 关键词使用 Naive UI 的 `Tag` 组件展示
- Token 计数使用小字灰色文本
- 搜索框使用 Naive UI 的 `Input` 组件，带搜索图标

### 11.3 路由改造

所有需要三栏布局的页面（对话、预设编辑、世界书编辑、正则编辑）放在同一个布局容器下，通过子路由切换中间区域内容：

```typescript
const routes = [
  {
    path: '/login',
    name: 'Login',
    component: () => import('../views/LoginView.vue'),
    meta: { title: '登录', requiresAuth: false }
  },
  {
    // 共享三栏布局的父路由
    path: '/',
    component: () => import('../layouts/AppLayout.vue'),
    meta: { requiresAuth: true },
    children: [
      {
        path: '',
        name: 'Chat',
        component: () => import('../views/ChatView.vue'),
        meta: { title: 'Muse - 对话' }
      },
      {
        path: 'preset/:id',
        name: 'PresetEditor',
        component: () => import('../views/PresetEditorView.vue'),
        meta: { title: 'Muse - 预设编辑' }
      },
      {
        path: 'worldinfo/:id',
        name: 'WorldInfoEditor',
        component: () => import('../views/WorldInfoEditorView.vue'),
        meta: { title: 'Muse - 世界书编辑' }
      },
      {
        path: 'regex/:id',
        name: 'RegexEditor',
        component: () => import('../views/RegexEditorView.vue'),
        meta: { title: 'Muse - 正则编辑' }
      }
    ]
  }
];
```

### 11.4 AppLayout.vue 布局容器组件结构

`AppLayout.vue` 作为所有主路由的父布局，包含左侧边栏、右侧面板和中间的 `<router-view>`：

```html
<template>
  <div class="app-layout">
    <!-- 左侧边栏 -->
    <LeftSidebar v-if="appStore.leftSidebarVisible" />

    <!-- 中间主区域 - 由路由控制展示内容 -->
    <main class="main-content">
      <TopBar />
      <router-view v-slot="{ Component }">
        <transition name="fade" mode="out-in">
          <component :is="Component" />
        </transition>
      </router-view>
    </main>

    <!-- 右侧面板 -->
    <RightPanel v-if="appStore.rightPanelVisible" />

    <!-- 设置抽屉（全局） -->
    <SettingsDrawer v-model:visible="appStore.settingsDrawerVisible" />
  </div>
</template>
```

这样，无论用户在对话页（`/`）还是预设编辑页（`/preset/:id`），左右侧边栏始终保持不变，只有中间内容通过路由切换。

| 动画目标 | 动画类型 | 时长 | 缓动函数 |

| 右侧面板展开/折叠（PC） | `transform: translateX` + `margin-right` 推挤 | `300ms` | `cubic-bezier(0.4, 0, 0.2, 1)` |

| 主区域视图切换 | `opacity` 淡入淡出 + `translateX` 方向感 | `200ms` | `ease-out` |

### 12.2 主区域视图切换动画

中间主区域在对话视图和编辑视图之间切换时的过渡：

```css
/* 从对话视图进入编辑视图 */
.editor-enter-active {
  transition: opacity 200ms ease-out, transform 200ms ease-out;
}
.editor-enter-from {
  opacity: 0;
  transform: translateY(8px);
}

/* 从编辑视图返回对话视图 */
.chat-enter-active {
  transition: opacity 200ms ease-out, transform 200ms ease-out;
}
.chat-enter-from {
  opacity: 0;
  transform: translateY(-8px);
}
```

- 进入编辑视图：内容从下方淡入（暗示"深入"编辑）
- 返回对话视图：内容从上方淡入（暗示"返回"顶层）

### 12.3 微交互

- 按钮 hover：轻微背景色变化，`transition: 150ms`
- 列表项 hover：背景色变化，`transition: 100ms`
- 下拉菜单：`opacity` + `scaleY` 展开动画
- 输入框 focus：边框颜色渐变高亮
- 发送按钮：发送时有缩放动画反馈
- 右侧面板列表项点击：点击反馈涟漪效果

### 12.4 性能要求

- 所有动画使用 `transform` 和 `opacity` 属性，触发 GPU 加速
- 添加 `will-change` 属性给频繁动画的元素
- 使用 `contain: layout` 限制重绘范围
- 移动端减少或简化动画
- 视图切换使用 `v-show` + 过渡而非 `v-if` 销毁重建（对话视图建议保持alive避免重新加载）

## 十三、主题与视觉规范

### 13.1 整体视觉风格

参考 Google AI Studio 的设计语言：
- **简洁明快**：减少不必要的装饰元素
- **层级清晰**：通过背景色区分不同区域
- **留白充足**：内容之间有足够间距
- **圆角友好**：按钮和卡片使用 `8-16px` 圆角
- **阴影适度**：使用轻微阴影（`box-shadow`）区分浮层

### 13.2 颜色规范

**移除现有的科幻/赛博朋克风格**（如粒子特效、发光边框、网格背景等），改为 Google 风格的简洁设计。

**亮色主题：**
- 主背景：`#FFFFFF`
- 侧边栏/面板背景：`#F8F9FA`
- 编辑器背景：`#FFFFFF`（与主背景一致，编辑器内卡片用浅灰底色区分）
- 边框颜色：`#E0E0E0`
- 主文字：`#1F1F1F`
- 次级文字：`#5F6368`
- 主题色/强调色：`#1A73E8`（Google 蓝）或自定义品牌色
- hover 背景：`#F1F3F4`
- 激活/选中背景：`#E8F0FE`
- 编辑器卡片背景：`#F8F9FA`

**暗色主题：**
- 主背景：`#1E1E1E`
- 侧边栏/面板背景：`#252525`
- 编辑器背景：`#1E1E1E`
- 边框颜色：`#3C3C3C`
- 主文字：`#E3E3E3`
- 次级文字：`#9AA0A6`
- 主题色/强调色：`#8AB4F8`
- hover 背景：`#333333`
- 激活/选中背景：`#2D3748`
- 编辑器卡片背景：`#2A2A2A`

### 13.3 字体规范

- 主字体：`-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'Noto Sans SC', sans-serif`
- 代码/编辑器字体：`'JetBrains Mono', 'Fira Code', 'Source Code Pro', monospace`

- 正文字号：`14px`
- 辅助文字：`12px`

### 13.4 需要移除的现有元素

- 科幻网格背景（`sci-fi-grid-bg`、`sci-fi-grid-dots`）
- 粒子动画（`sci-fi-particles`、`sci-fi-particle`）
- 角落装饰（`sci-fi-corner`）
- 发光效果（`glow-soft`、`logo-glow`、`title-glow`）
- 渐变背景（`gradient-primary` 如果过于花哨）
- 过渡复杂的 CSS 动画

### 14.3 移动端编辑视图特殊处理

在移动端，当用户进入编辑视图时：
- 编辑视图占满整个屏幕（除顶部栏外）
- 顶部栏左侧显示明显的 `← 返回` 按钮
- 编辑器内容宽度 `100%`，padding 缩小为 `12px`
- 卡片（Prompt项/词条）全宽展示
- 文本编辑器最小高度适当缩小（`100px`）
- 右侧面板在编辑视图时自动关闭（移动端不需要同时看列表和编辑器）

### 14.4 触摸优化（移动端）

- 所有可交互元素最小触摸区域：`44px × 44px`
- 会话列表项高度不小于 `48px`
- 右侧面板列表项高度不小于 `56px`
- 支持左右滑动手势打开/关闭侧边栏（可选）
- 长按触发上下文菜单
- 拖拽排序在移动端使用长按+拖动
- 消息列表支持下拉刷新加载更多历史消息

## 十六、参考设计（Google AI Studio 关键特征总结）

基于参考图片，Google AI Studio 的 UI 关键特征如下：

1. **极简顶部栏**：左侧有 Logo 和侧边栏切换按钮，中间有模型选择器（带模型图标和下拉箭头），右侧有设置和用户头像
2. **左侧边栏**：顶部 `+ New chat` 按钮非常醒目，下方按时间排列的对话历史列表，底部有设置入口
3. **主聊天区**：消息内容区居中、留白充裕，底部输入框带圆角、居中放置
4. **右侧配置区**：在编辑 prompt 时，右侧有运行设置面板，包含模型选择、Temperature 等参数滑块
5. **配色**：深色模式为深灰（`#1E1E1E`）背景，亮色模式为白色背景，强调色为 Google 蓝
6. **字体**：使用 Google Sans 或 Roboto，中文使用 Noto Sans SC
7. **圆角**：按钮和输入框圆角较大（`20-28px`），卡片圆角 `12-16px`
8. **无多余装饰**：没有渐变、发光、粒子等效果，非常干净

### 本方案与 Google AI Studio 的差异说明

| 特征 | Google AI Studio | 本方案 |
|------|-----------------|--------|
| 右侧面板 | 仅有模型参数配置 | 扩展为四个 Tab（模型/预设/世界书/正则）的列表选择器 |
| 编辑位置 | 主区域就是 Prompt 编辑区 | 主区域默认是对话，点击右侧面板具体项后切换为编辑器 |
| 左侧边栏 | 只有对话历史 | 增加角色管理子面板 |
| 视图切换 | 有对话/Prompt编辑两种模式 | 有对话/预设编辑/世界书编辑/正则编辑四种模式 |

**核心设计理念**：借鉴 Google AI Studio 的简洁美观和空间利用方式，但根据 Muse 项目实际需要（预设管理、世界书、正则等 SillyTavern 特有功能）进行扩展。**右侧面板做选择，中间区域做编辑**，避免把复杂编辑功能塞进窄小的侧边栏中。
